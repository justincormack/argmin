# Phase 9.10 Test Harness Audit

This audit records test and helper shapes that matter for the Phase 9
de-single-process closeout. The goal is not to remove every local helper:
parser/model/unit tests and deliberate crash-state seeders are useful. The goal
is to make sure tests that claim cross-process, restart, convergence, race,
drain, reclaim, lifecycle, cache-freshness, or scavenger correctness are not
passing only because they share local locks, local wakeups, shared caches,
process-global hooks, or direct `PgStore` state.

Classifications:

- `production-shaped`: exercises the public `StorageCluster`/`Coordinator`
  path in the same authority shape as runtime code; for cross-process cache
  assertions this requires independent cache/watch state.
- `acceptable local unit`: intentionally tests local-only logic, raw helpers,
  parsers, models, codecs, or storage-node internals.
- `crash-state seeding`: uses raw store or test hooks to construct a partial,
  stale, corrupt, or otherwise unreachable state, then verifies recovery through
  production code.
- `suspect`: the test claims a cross-process or restart/concurrency invariant
  but still depends on a local-only authority shape. These need a harness change,
  a new production-shaped regression, or a narrower name/comment.
