# SessionId Hardening Plan

## Status

Planned.

This is a narrower internal follow-up after the completed bucket/object and
upload-id hardening work.

## Trigger

`SessionId` still has the old permissive string-wrapper shape in
[crates/storage/src/types.rs](/home/justin/src/github.com/justincormack/argmin/crates/storage/src/types.rs):

1. it is still defined through `string_newtype!`
2. it still has infallible `From<&str>` / `From<String>` construction
3. it still implements `Deref<Target = str>`
4. `FromSql` still wraps stored text without revalidation

The coordinator/storage boundary also still accepts raw `&str` session IDs for
streaming session operations, for example in:

1. [crates/storage/src/traits.rs](/home/justin/src/github.com/justincormack/argmin/crates/storage/src/traits.rs)
2. [crates/storage/src/pg_store.rs](/home/justin/src/github.com/justincormack/argmin/crates/storage/src/pg_store.rs)
3. [crates/server-core/src/coordinator.rs](/home/justin/src/github.com/justincormack/argmin/crates/server-core/src/coordinator.rs)
4. [crates/server-http/src/http/mod.rs](/home/justin/src/github.com/justincormack/argmin/crates/server-http/src/http/mod.rs)

## Decision

Treat `SessionId` as an internal validated identifier type and remove the
remaining implicit-string footguns around it.

Unlike `UploadId`, this is not primarily an AWS-wire-compatibility project.
`SessionId` is currently:

1. generated by Argmin
2. stored internally
3. propagated through our own streaming control flow
4. not exposed as a client-supplied request identifier

So the design target is internal type safety:

1. `SessionId` should model the server-issued shape explicitly
2. coordinator/storage/PG helpers should take `&SessionId`, not raw `&str`
3. string boundaries should be explicit via `.as_str()`
4. persistence should revalidate on load

## Why this work is needed

This is lower priority than the completed identifier hardening work, but it is
still worth doing because:

1. the current type name suggests a meaningful invariant that the type does not
   actually enforce
2. raw `&str` session IDs still cross internal coordinator/storage/hash
   boundaries
3. the old `Deref<str>` / infallible-construction shape keeps the same class of
   accidental method-resolution and generic-string footguns we just removed for
   other identifiers
4. `StreamUploadRecord` already stores `SessionId`, so the remaining raw-string
   seams are mainly legacy API shape rather than a real modeling need

## Goals

1. Make `SessionId` a validated type matching the server-issued format.
2. Remove implicit string conversions and `Deref<str>` from `SessionId`.
3. Type coordinator/storage/PG streaming-session APIs as `&SessionId`.
4. Store `SessionId` in HTTP streaming bindings and internal request state
   instead of `String`.
5. Add direct persistence and boundary tests for the new typed shape.

## Non-goals

1. AWS behavior probing or AWS-conformance work for `SessionId`.
2. Redesigning the streaming upload/session feature set itself.
3. Introducing a migration layer for previously stored invalid session IDs; the
   repository is still pre-release.

## Proposed validation model

`SessionId` should match the shape Argmin already emits today.

Current generation uses 16 random bytes hex-encoded, which means:

1. exactly 32 characters
2. lowercase hexadecimal only: `[0-9a-f]`

That is a good invariant for the type:

1. it matches current production behavior
2. it is compact and easy to audit
3. it avoids inventing any broader internal grammar than necessary

## Work Plan

## Phase 1: Make SessionId a strict internal type

1. Rework `SessionId` in
   [crates/storage/src/types.rs](/home/justin/src/github.com/justincormack/argmin/crates/storage/src/types.rs)
   to use fallible construction with a dedicated validation error.
2. Remove infallible `From<&str>` / `From<String>` construction.
3. Remove `Deref<Target = str>` from `SessionId`.
4. Make `FromSql` revalidate stored values through the typed constructor.
5. Add direct type-level tests for valid, invalid-length, and invalid-character
   session IDs.

Exit criteria:

1. `SessionId` cannot be built casually from arbitrary strings.
2. stored rows have one explicit audited load rule.
3. the type-level tests pin the emitted 32-char lowercase-hex shape.

## Phase 2: Type the internal streaming-session boundary

1. Change streaming-session storage traits in
   [crates/storage/src/traits.rs](/home/justin/src/github.com/justincormack/argmin/crates/storage/src/traits.rs)
   to take `&SessionId`.
2. Update `PgStore` implementations and any helper methods to use typed session
   IDs end to end.
3. Update coordinator streaming APIs and helpers in
   [crates/server-core/src/coordinator.rs](/home/justin/src/github.com/justincormack/argmin/crates/server-core/src/coordinator.rs)
   so streaming session operations no longer take raw `&str`.
4. Update PG/hash helpers that currently key off session ID strings so the typed
   identifier flows to the explicit string boundary instead.

Exit criteria:

1. production coordinator/storage/PG session APIs no longer take raw `&str`
   session IDs.
2. string use is explicit at SQL and formatting boundaries only.

## Phase 3: Type HTTP streaming bindings and test helpers

1. Change `StreamObjectBinding` and related streaming HTTP context structs in
   [crates/server-http/src/http/mod.rs](/home/justin/src/github.com/justincormack/argmin/crates/server-http/src/http/mod.rs)
   to store `SessionId` instead of `String`.
2. Update streaming serve-path helpers in
   [crates/server-http/src/http/serve.rs](/home/justin/src/github.com/justincormack/argmin/crates/server-http/src/http/serve.rs)
   so they keep typed session IDs through append/finalize/abort flows.
3. Update tests and helpers that currently construct session IDs through raw
   strings by convention.

Exit criteria:

1. session IDs remain typed through HTTP streaming contexts.
2. remaining raw string conversions are local and explicit.

## Phase 4: Coverage and closeout

1. Add persistence regressions for invalid stored session IDs.
2. Add targeted coordinator/storage tests proving typed session IDs survive the
   main stream-put and stream-part paths.
3. Audit the remaining `session_id: &str` or `String` production surfaces and
   either type them or document why they are intentionally left raw.
4. Update this plan with the final boundary shape and move it to
   `plans/completed/` once done.

Exit criteria:

1. the typed `SessionId` boundary is covered by direct tests.
2. the plan records any intentionally remaining raw seams.
3. the final state is documented accurately.
