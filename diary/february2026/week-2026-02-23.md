# Week Diary: 23-27 February 2026

## Monday 23 February — Project kickoff, EC engine, and placement

Started the argmin project from scratch. The goal: build an S3-compatible
object storage system in Rust, erasure-coded with ISA-L.

**Morning: setup and planning**
- Set up the agent environment and initial project structure.
- Wrote the territory map (`plans/territory-map.md`) breaking the system into
  9 subsystems and defining the v1-minimal milestone: a single-process S3 server
  with no distribution, synchronous IO, per-PG SQLite metadata.
- Pulled in a Rust memory guide as reference material.

**Early afternoon: erasure coding engine (Phase 1a)**
- Wrote the EC plan and then the first version of the `ec` and `ec-sys` crates —
  a Rust wrapper around ISA-L's Reed-Solomon erasure coding.
- First implementation led to an `engineering_lessons.md` writeup. Key surprises:
  - **AI-generated summaries of C library behaviour can be subtly wrong.** The ISA-L
    SIMD loop exit condition was described incorrectly. Had to read the actual header
    and assembly source. Lesson: read the source, distrust summaries.
  - **UB in tests**: the initial `ShardSizeTooLarge` tests created fake large slices
    using `from_raw_parts`, which is UB in Rust even if never dereferenced. Fixed by
    extracting a `check_shard_size` helper so tests validate the boundary directly.
  - **`saturating_mul` for scratch sizes**: on 32-bit targets, `m * i32::MAX` can
    overflow `usize`. Changed to saturating arithmetic so the error path is hit
    instead of wrapping silently.
- Wrote up notes on API design philosophy: callers own all buffers, the library
  owns nothing. Error types carry only fixed-size data (no `String`, no `Vec`).
  Push size calculations to the caller via `*_scratch_size()` functions.

**Late afternoon: placement crate (Phase 1b)**
- Planned and implemented the placement crate using weighted rendezvous hashing
  (HRW). Went through several plan iterations:
  - Started with a simple approach, then redesigned to compute placement nodes
    in a streaming fashion using a constant-size buffer (stack arrays sized to
    `MAX_SHARDS=32`).
  - Added variable topology support (rack, machine, disk levels).
  - Score function: `score = -ln(U) / weight` where U is derived from
    `rapidhash(key||node_id)`.
- Implemented with partition matroid constraints for failure domain separation.
  61 tests including zero-allocation verification (thread-local `Cell<bool>` for
  counting allocations, not global atomics — lets tests run in parallel).

**Evening: self-test**
- Added an erasure coding self-test that runs at startup to verify ISA-L is
  working correctly on the host CPU.


## Tuesday 24 February — Planning day

Light commit day (just one: adding the self-test to the EC plan). Most of the
day was spent on design work that would land on Wednesday:
- Working through metadata and cluster design decisions.
- Thinking about the PG (placement group) model and how per-PG SQLite databases
  would work for the single-node case.
- Decided to use a fully buffered (not streaming) approach for v1-minimal, with
  a 256 MB cap per object. Streaming would require reworking the entire pipeline.


## Wednesday 25 February — Storage layer and full S3 server

The big build day. Went from "we have EC and placement libraries" to
"you can run AWS CLI commands against it."

**Morning: cleanup and metadata design**
- Removed the dependencies clone script, decided to keep things in-repo.
- Extensive work on metadata plans (`plans/metadata-cluster-design.md`),
  working through PG design options and how rendezvous hashing applies to PGs.

**Afternoon: the minimal starting point**
- Defined a "really minimal non-distributed non-async starting point" — the
  architectural skeleton that wires everything together with trait method calls
  instead of RPC.

**Late afternoon/evening: three crates in rapid succession**

1. **crc64 crate** — CRC-64/NVME via ISA-L's `crc64_rocksoft_refl`. Tiny FFI
   wrapper, completed Phase 1.

2. **storage crate (Phase 2)** — Per-PG shard storage with:
   - `FileShardStore`: file-per-shard on disk, atomic writes (temp → fsync → rename)
   - Per-PG SQLite in WAL mode for shard index and object metadata
   - `SqliteBucketDb` for the bucket table (placeholder for future Raft service)
   - CRC64-NVME integrity verification on every read

3. **S3 server layer (Phase 3)** — The whole HTTP frontend, auth, and coordinator:
   - `auth` crate: AWS Signature V4 verification using `ring` for HMAC-SHA256
   - `server` crate: HTTP frontend with `tiny_http`, S3 routing, XML responses
   - Coordinator: S3 operation → metadata blob prepend → EC encode → derive PG →
     write shards → commit object record

By end of Wednesday, the AWS CLI worked for basic operations: `create-bucket`,
`cp`, `ls`, `head-object`. Updated the README with working examples.

**Key surprise**: `tiny_http::Request` consumes self in `respond()`, so the
parsed S3 request and original HTTP request must both be available. The plan
hadn't accounted for this ownership constraint — had to return both as a pair.


## Thursday 26 February — Hardening, compatibility, and features

The marathon day. 20+ commits covering security hardening, compatibility fixes,
test coverage, and significant new features.

**Morning: review and hardening (09:51-10:44)**
- Added implementation notes documenting all deviations from the plan (7 items,
  including: placement crate not used for v1-minimal PG derivation — just
  `rapidhash(bucket/key) % pg_count`; HeadObject calls GetObject internally; etc.)
- Security hardening pass:
  - Time-skew enforcement (±15 min on `x-amz-date` to prevent replay attacks)
  - Input validation (bucket names per AWS rules, object keys 1-1024 bytes)
  - Metadata value sanitization (reject ASCII control characters)
  - Payload integrity verification (recompute SHA-256 when claimed hash provided)
- **Unexpected**: initially the time-skew check was silently skipped when
  `x-amz-date` was malformed. Changed to reject malformed timestamps — skipping
  the check would weaken replay protection.
- SigV4 fixes: double-encoding, payload integrity, header normalization, list
  continuation token handling.

**Late morning: test coverage (11:08-12:27)**
- Added 107 unit tests to close coverage gaps (79.8% → 88.4%)
- Updated README with working AWS CLI examples
- Further branch coverage improvements for sigv4, coordinator, xml, and etag

**Early afternoon: Ceph compatibility (13:25-14:04)**
- Ran parts of the Ceph S3 test suite and found 7 compatibility issues:
  1. Trailing slashes in object keys were being blanket-stripped
  2. Non-ASCII bytes (>= 0x7F) in metadata header values not rejected
  3. MaxKeys=0 should return empty result, not scan all PGs
  4. Common prefixes not included in KeyCount for ListObjectsV2
  5. CreateBucket not idempotent for same owner
  6. No ListObjects v1 support (only v2) — added V1 with Marker/NextMarker
  7. Negative and non-numeric Content-Length not rejected
- Added `DeleteObjects` (bulk delete, POST with `?delete`) and
  `ListObjectVersions` — needed by the Ceph test suite's cleanup phase.
- Added end-to-end tests for the Ceph cleanup workflow.
- Added property-based tests (proptest) for auth, crc64, placement, and storage.
- Added a debug CLI for read-only SQLite metadata inspection.

**Afternoon: Range requests (16:59)**
- Major feature: HTTP Range request support with optimized shard reading.
- Key design: instead of reading all k+m shards, read only the data shards
  covering the needed byte range. Added `total_size` field to `ObjectRecord`
  to enable the shard planning math.
- Backward compatibility: objects written before this change (total_size=0)
  fall back to the legacy read-all-data-shards path.
- Wrote a design document (`plans/range-request-design.md`).

**Late afternoon: fault injection (17:40)**
- Designed and implemented a fault injection framework for EC shard testing.
- Test-only (`#[cfg(test)]`), not shipped in production.
- Supports: missing data, corrupt data (bit flips), failed writes, IO errors,
  CRC mismatch simulation.
- Wrote a plan document (`plans/fault-injection.md`).

**Evening: conditional requests and CopyObject (19:41-22:13)**
- Implemented full conditional request support per RFC 7232:
  - `If-Match`, `If-None-Match`, `If-Modified-Since`, `If-Unmodified-Since`
    for reads (GET/HEAD/Range)
  - `If-Match` and `If-None-Match:*` for writes (PUT)
  - `If-Match` for deletes
  - Wildcard (`*`) and comma-separated ETag lists
  - Proper 304 Not Modified and 412 Precondition Failed responses
- Implemented S3 CopyObject operation (PUT with `x-amz-copy-source` header):
  - Extracted `write_object_inner` from `put_object` as shared write path
  - Copy source conditions (`x-amz-copy-source-if-*`) — all failures return 412
  - Metadata directive: COPY (preserve source) vs REPLACE (use request headers)
  - Same-key copy for in-place metadata updates
  - XML `<CopyObjectResult>` response
  - 10 integration tests covering cross-bucket, same-key, conditional, etc.

**Late evening: encoding fixes (22:03-22:13)**
- Fixed double-encoding of percent-encoded URI paths in SigV4 canonical requests.
  The `uri_encode_path` function was re-encoding existing `%XX` sequences.
- Moved percent-decoding of object keys to the routing layer so keys are stored
  in logical form in the database, not URL-encoded.
- Improved DB error messages to include the underlying SQLite error.


## Friday 27 February — Versioning, auth, POST Object, and integration tests

Wrote the diary in the morning, then had the most productive day of the week.

**Morning: cleanup and hardening (09:03-10:16)**
- Wrote the diary.
- Big cleanup commit: improved S3 request handling, error messages, and
  metadata headers. Aligned behavior with s3-tests and AWS expectations —
  fixed edge cases in routing, canonicalization, and response headers.
  Stored/returned standard object metadata (Cache-Control, Expires,
  Content-Disposition/Language). Tightened delete-objects XML parsing.
  35 files changed.
- Removed legacy `total_size==0` backward-compat fallback paths from the
  coordinator. No existing installations to migrate, so cut ~170 lines
  of dead code. All reads now unconditionally use `read_range`.

**Early afternoon: object versioning (12:59-14:45)**
- Planned and implemented S3 object versioning in two commits:
  1. **Infrastructure**: split metadata/shard PG routing (metadata uses
     `derive_pg(bucket, key)`, shards use `derive_pg_shards(bucket, key,
     version_id)` so different versions distribute across PGs). Changed
     version_id from String to u64 throughout. Added bucket versioning
     state management (Disabled/Enabled/Suspended). Expanded PgMetadataStore
     trait with `get_object_version`, `delete_object_version`,
     `list_object_versions`, `next_version_id`. Rewrote `list_objects` SQL
     with CTE for correct versioning semantics.
  2. **Wiring**: connected the storage layer's versioning methods to the
     coordinator and HTTP frontend. Put generates version IDs when bucket
     versioning is enabled. Get/head accept optional `?versionId=`.
     Delete implements three-way dispatch: physical delete (unversioned),
     permanent version delete (specific versionId), and delete marker
     insertion (versioned without versionId). ListObjectVersions returns
     proper Version/DeleteMarker XML elements with IsLatest tracking.

**Afternoon: authentication and authorization (16:30)**
- Major feature: SigV4 header and presigned URL authentication with
  per-bucket owner-based authorization. New `authenticate_request()`
  entrypoint returns an `AuthContext` carrying the caller's principal
  identity. Server enforces read/write access based on bucket ownership.
  Support for public-read ACLs via `x-amz-acl` header. Anonymous access
  falls back gracefully. Request timestamp skew enforcement (±15min) and
  payload SHA-256 integrity verification.

**Evening: Ceph compat, POST Object, and integration tests (20:00-22:05)**
- Fixed 7 more S3 compatibility issues found by Ceph s3-tests:
  don't emit `x-amz-version-id` for unversioned objects, add `response-*`
  query parameter overrides for GetObject, fix `If-Match:*` on non-existent
  key (404 not 412), add delete marker headers, reject presigned URLs with
  `X-Amz-Expires=0`, fix `BucketAlreadyExists` error code.
- Implemented S3 POST Object with SigV2 form-based authentication —
  a completely different auth path from the rest of the API. New multipart
  form parser, policy validation with correct error mapping (structural
  issues → 400, condition failures → 403, content-length-range → 400).
  Features: `${filename}` substitution, `success_action_status`, SHA-256
  checksum verification. Passes 31/40 Ceph POST tests (remaining 9 need
  public-read-write ACL or SSE support).
- Planned and built the Rust integration test framework (`crates/s3-tests`):
  uses the official AWS SDK for Rust as a completely independent S3 client
  to validate the wire protocol. 45 tests (23 bucket CRUD + 22 object CRUD)
  running against a local TestServer on a random port. Can also run against
  external endpoints (real AWS S3) via environment variables.
  - Interesting concurrency challenge: hyper's HTTP connection pool holds
    stale keep-alive connections for 90s, causing tests to hang. Fixed with
    `operation_attempt_timeout(5s)` on the SDK client.
  - Another challenge: `HttpFrontend` contains SQLite via `RefCell` (not
    `Send`/`Sync`), so the test server spawns 8 handler threads each
    constructing their own complete server stack.

### Key things that were unexpected

1. **ISA-L C library summaries were wrong** — had to read actual assembly source
   for the SIMD loop exit condition. "Read the source, distrust summaries."
2. **UB in Rust tests** — creating fake large slices with `from_raw_parts` is UB
   even if never dereferenced. Had to restructure test approach.
3. **tiny_http ownership model** — `Request::respond()` consumes self, forcing
   the parsed request to be a separate struct rather than borrowing from the
   original request.
4. **Malformed timestamps should be rejected, not skipped** — initially the
   time-skew check was silently skipped on bad `x-amz-date`, which would weaken
   replay protection.
5. **SigV4 double-encoding** — percent-encoded characters in URIs were being
   re-encoded, breaking signatures for keys with special characters.
6. **Ceph test suite surfaced 14+ compat issues** across two rounds of fixes —
   trailing slash handling, ListObjects v1 vs v2 routing, MaxKeys=0 behavior,
   Content-Length validation, version-id headers, response-* query params,
   If-Match:* on missing keys, delete marker headers, presigned URL expiry.
7. **Placement crate not needed for v1-minimal** — PG derivation is just
   `rapidhash(bucket/key) % pg_count`, not the full rendezvous hashing placer.
   The placement crate is for the distributed case (assigning shards to nodes).
8. **Keys must be stored decoded** — URL-encoded keys in the database cause
   mismatches when clients send the same key with different encoding.
9. **POST Object uses a completely different auth scheme** — SigV2 with
   HMAC-SHA1 over a base64-encoded policy document, embedded in multipart
   form fields. Error semantics differ too: structural policy errors → 400,
   condition failures → 403, but content-length-range → 400.
10. **Hyper connection pool causes test hangs** — idle keep-alive connections
    (90s default timeout) block tiny_http's internal threads, causing new
    requests to stall. Fixed with 5s `operation_attempt_timeout` on the
    AWS SDK client.
