## Tuesday 1 April — Lifecycle expiration and request checksums

**Lifecycle expiration.** Built the lifecycle execution engine in four phases:

1. **Configuration support** — `PutBucketLifecycleConfiguration`,
   `GetBucketLifecycleConfiguration`, `DeleteBucketLifecycleConfiguration`
   with full rule parsing (Expiration, NoncurrentVersionExpiration,
   AbortIncompleteMultipartUpload, filters, tags).
2. **Expiration sweep** — background sweeper that evaluates lifecycle rules
   against current objects and creates delete markers or removes expired
   objects. Manual sweep trigger for testing.
3. **Noncurrent expiration** — expired noncurrent versions are removed.
   `NewerNoncurrentVersions` count is respected.
4. **Multipart abort** — incomplete multipart uploads older than the
   configured threshold are aborted by the sweeper.

Shared the lifecycle sweeper instance across coordinators so all request
paths can trigger sweeps.

**Request checksum compatibility.** Matched AWS request checksum behavior —
the `x-amz-checksum-*` request headers and `x-amz-request-algorithm`
trailing checksums now validate correctly for all operation types.

**Property testing expansion.** Added storage property test helpers,
differential properties for storage operations and pagination, and lifecycle
property tests verifying that sweep/expire/abort operations maintain storage
invariants.

**Test infrastructure.** Split HTTP transport checks into a new
`s3-http-tests` crate for tests that exercise raw HTTP behavior (malformed
requests, connection handling) separately from S3 API semantics.

## Thursday 3 April — SSE-S3 and ACL completion

**SSE-S3 (server-managed encryption).** Completed the full implementation:

- Default encryption rollout — buckets can be configured with default
  SSE-S3 encryption via `PutBucketEncryption`. New objects are
  automatically encrypted.
- Policy integration — bucket policies can require SSE-S3 encryption
  via `s3:x-amz-server-side-encryption` condition keys.
- Interface cleanup — unified the SSE-C and SSE-S3 encryption paths
  through a common encryption layer, tightened encryption boundaries
  between the HTTP and core layers.

**ACL compatibility follow-up:**

- Implemented `authenticated-read` bucket ACL (AuthenticatedUsers group
  grant). Previously returned 501.
- Implemented `aws-exec-read` canned ACL.
- Added bucket ACL grant matrix coverage — canonical user grants with
  all five permission types (READ, WRITE, READ_ACP, WRITE_ACP,
  FULL_CONTROL), verified cross-account.
- Added object ACL grant authorization coverage.
- Extended bucket ACL compatibility coverage.

**Bucket policy.** Implemented `IfExists` condition operators
(`StringLikeIfExists`, `StringEqualsIfExists`, etc.) — standard AWS IAM
feature where absent condition keys evaluate as vacuously true.

**Ceph parity.** Added versioning concurrency coverage. Created the Ceph
closeout plan tracking remaining test parity gaps.


## Friday 4 April — Ownership conformance and directory bucket guards

**Ownership conformance.** Aligned ACL and expected-bucket-owner behavior
with AWS — tightened how ownership controls interact with canned ACLs and
cross-account operations. Archived the ownership conformance follow-up plan

**Directory bucket guards.** AWS returns specific errors when directory
bucket features (like `CreateSession`) are used on standard general-purpose
buckets. Added rejection for directory-bucket-only APIs on our standard
buckets to match.


## Saturday 5 April — AWS region conformance and namespace support

Driven by running the full test suite against real AWS S3, fixed a series
of conformance issues:

- **aws-chunked content-encoding** — aligned handling with AWS for requests
  that declare `aws-chunked` but don't actually use chunked framing.
- **Metadata limits** — matched AWS limits on user metadata size and count.
  Default object checksums now match AWS behavior.
- **Completed multipart tombstones** — clear tombstone records when a bucket
  is deleted, preventing stale metadata from accumulating.
- **Wrong-region responses** — AWS returns specific redirect-style errors
  when you hit a bucket in the wrong region. Implemented matching error
  responses.
- **Region-aware external tests** — the test suite now correctly handles
  region-specific bucket creation and endpoint routing when running against
  AWS.
- **Auth region behavior** — aligned SigV4 region validation edge cases
  with AWS.
- **Bucket list regression** — fixed `CommonPrefixes` deduplication in
  list-objects responses. Hardened versioning list test for AWS eventual
  consistency propagation delays.
- **Account-regional bucket namespace** — implemented S3's per-account,
  per-region bucket namespace model for correct bucket ownership and
  region routing.
- **Documentation** — added notes for website hosting behavior and
  requester pays as future work items.
