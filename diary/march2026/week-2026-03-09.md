# Week Diary: 9–15 March 2026

144 commits in 7 days. This week was about crate restructuring, streaming
everything, a unified segment model, and driving test coverage toward
completeness.


## Monday 9 March — Request type refactoring

Continued the request struct work started the previous week. Introduced typed
request structs for the remaining coordinator methods:

- `CopyObjectRequest`, `UploadPartCopyRequest`, and `CopySource`
- `FinalizeStreamPutRequest` and `FinalizeStreamPartRequest`
- Replaced ad-hoc checksum tuples with `RawChecksum` in the streaming part path

This was the final cleanup needed before the crate split — every coordinator
method now takes a single well-typed request struct instead of a long parameter
list.


## Tuesday 10 March — The great crate split

**The biggest structural change to the project so far.** Split the monolithic
frontend crate into three pieces:

1. **`server-core`** — coordinator logic, authorization, all business rules
2. **`server-http`** — HTTP parsing, routing, XML rendering, response formatting
3. **`s3-types`** — shared S3 domain types (`VersionId`, `BucketName`, etc.)

Also extracted `checksum` domain types into their own crate.

The split was done methodically: rename the package/directory first
(`frontend` → `server-http`), then extract `server-core` with all coordinator
logic, then move authorization into server-core method by method (bucket read,
object read, copy, put, delete, bucket subresource, write, create/list
buckets). Each authz migration was its own commit so the test suite stayed
green throughout.

Other work: sealed `MetadataBlob` internals, moved conditional header parsing
to the HTTP layer, introduced `MultipartChecksumConfig` to enforce valid
algorithm/type combinations, split the runtime from server-http. Made
everything pedantic-clippy clean.

Also added branch coverage tests for `placer.rs` and planned the reclamation
race condition fix.

- 16 MiB streamed upload tests

**Coverage offensive.** Switched the coverage script to measure integration

- Checksum `types.rs` full branch coverage
- Removed dead `CredentialStore::get()` method
- Request parsing coverage (copy source, URI)

- Dead batch parser deletion in multipart.rs

**AWS compatibility fixes:**
- Malformed Range headers silently ignored (matches AWS)
- Error codes for malformed XML aligned with AWS
- Chunked upload hardening for AWS edge cases
- Reverted an overly aggressive body size limit (10 MB → 256 MB → streaming)

Added notes to AGENTS.md about always matching AWS S3 behavior and running
full tests before committing.


## Thursday 12 March — Streaming reads, reclamation, and XML migration

Three major workstreams running in parallel.

**Streaming reads.** The read path went fully streaming:

- New `StreamingReadHandle` type for GET responses
- `GetObjectRange` streams directly from storage through EC decode
- `GetObjectPart` (multipart part-number queries) streams similarly
- Copy-source reads moved to stepped readers
- Snapshot multipart read metadata before releasing PG locks (fixes a
  race where metadata could change between lock release and read)

**Payload reclamation.** Built the background reclamation system:

- Introduced `GenerationId` to separate payload identity from `VersionId`
  (a version can be overwritten but the old payload must survive until
  all readers finish)
- Read leases protect in-flight readers from reclamation
- Background worker queue drains reclaim records asynchronously
- Chunk manifest and multipart reclaim record types
- Bucket deletion now waits for background reclaim to drain
- Integration tests for deferred reclamation timing

**XML parser migration.** Replaced all hand-rolled XML parsing with
`quick-xml`:

- Versioning, tagging, delete objects, CORS, bucket policy
- Tag count helper replaced with parser-based implementation
- Object tagging made part of atomic writes (not a separate PUT)
- Tagging support added to POST Object
- Malformed tagging XML properly rejected

Also improved XML integration coverage in s3-tests.

## Saturday 14 March — Unified segment model

**The segment redesign.** Replaced the dual "inline vs chunk-manifest"
storage model with a single unified segment model. This was a multi-phase
refactor:

1. **Phase A: Metadata generalization.** Renamed "chunks" to "segments"
   throughout the codebase. Generalized committed and staging payload
   metadata to use segment records uniformly. Both buffered objects and
   streaming objects now store data as segments — the only difference is
   whether segments are written atomically or incrementally.

2. **Routing buffered writes through segments.** Buffered object writes
   and buffered multipart parts now create segment manifests, eliminating
   the special-case inline storage path.

3. **Unified reads.** All reads go through segment manifests. Retired
   the special-case segment manifest naming that distinguished inline
   from streamed objects.

4. **Segment checksums.** Added integrity checksums for bounded reads,
   verified on the read path.

Also completed the XML request parser migration plan, planned read-path
performance optimization, added a note on banded segment placement, and
stubbed `GetBucketPolicy` returning `NoSuchBucketPolicy`.


## Sunday 15 March — Illegal states, dead code, and AWS conformance

**Illegal-state interface cleanup.** With the unified segment model in place,
cleaned up interfaces that previously had to handle impossible states. The
type system now makes illegal storage layouts unrepresentable.

**Dead code removal.** Removed the old `put_object` and `upload_part`
non-streaming coordinator methods. These were superseded by the streaming
path and had become dead code.

**Coverage gap analysis.** Analyzed the remaining 224 uncovered "functions"
in `pg_store.rs`. Found that ~185 were `.map_err()` closures and error-only
branches. Wrote 6 new s3-tests targeting genuinely reachable gaps:

- `ListObjectVersions` with key-marker-only pagination
- `ListMultipartUploads` with key-marker-only pagination
- Put/delete tagging on nonexistent keys (NoSuchKey)
- Large PUT on versioned bucket (versioned INSERT branch)
- `CompleteMultipartUpload` on versioned bucket

Added 24 storage-layer unit tests for uncovered pg_store methods.

**NoSuchVersion fix.** Discovered via AWS testing that `GetObjectTagging`
on a deleted version-id returns `NoSuchVersion`, not `NoSuchKey`. Added a
`VersionNotFound` error variant and updated all version-specific lookup
paths in the coordinator. Also updated `delete_object` to handle
`VersionNotFound` for idempotent versioned deletes.

**Housekeeping:** Archived completed plans (territory map, storage node
design, metadata cluster design, streaming transfers, HTTP storage
boundary). Documented segment PG placement tradeoffs. Narrowed the AWS
auth follow-up plan scope.


## Week summary

This week transformed the project's internal architecture while maintaining
external behavior. The major milestones:

1. **Crate split** — monolithic frontend → `server-core` + `server-http` +
   `s3-types` + `checksum`. Clean separation of HTTP concerns from business
   logic. Every coordinator method now takes typed request structs.

2. **Fully streaming IO** — all upload paths (PUT, POST, UploadPart) and
   all read paths (GET, GET with Range, GET with partNumber, CopySource)
   now stream end-to-end. No object size limits.

3. **Unified segment model** — replaced the dual inline/chunk-manifest
   storage model with a single segment-based model. Eliminated entire
   categories of impossible states from the type system.

4. **Background reclamation** — payload lifecycle managed through
   GenerationId and read leases. Background workers drain reclaim queues.
   Bucket deletion waits for reclamation to complete.

5. **XML parser migration** — all XML parsing moved to quick-xml with
   proper error handling and malformed input rejection.

6. **Coverage and AWS conformance** — systematic coverage analysis,
   targeted test writing, NoSuchVersion fix, owner identity compatibility,
   ACL surface completion.

The storage pipeline is now: HTTP stream → auth → segment buffering →
EC encode → PG routing → shard write → segment manifest commit. Reads
reverse through segment manifests → shard read → EC decode → HTTP stream.
The unified segment model means there's exactly one code path for each
direction, regardless of object size or upload method.

Test count: ~1100+ across the workspace. The coverage script now measures
integration tests only, which is a better signal for externally observable
correctness.
